# 构建、部署和移植

## 在其他电脑继续开发

安装 Node.js 与 Git 后，克隆仓库并运行 `npm ci`。提交的 `package-lock.json` 用于复现依赖；不要把原电脑的 `node_modules` 复制过去。

构建和运行都不依赖原电脑的盘符、用户名或局域网 IP。

## 部署网页

```bash
npm ci
npm run build
npm run preview
```

构建产物只有 `dist/` 中的静态文件。部署时上传整个目录的内容到静态托管服务，不需要 Node 后端、数据库或运行时环境变量。

项目使用 `vite build --base=./`，资源地址相对入口文件生成，适合托管在域名根目录或项目子目录。保留 `assets/` 目录和文件名，不要只上传 `index.html`。部署后通过 HTTP/HTTPS 访问；双击本地 HTML 文件不等同于部署。

GitHub Actions 验证成功后提供 `2048-static-site` 构建附件，可从 Actions 对应运行的 Artifacts 下载。附件有保留期限；长期版本应从指定提交重新构建或另建正式 Release。

**上传代码仓库不等于发布在线游戏。** 当前 CI 只检查和提供产物，不会自动启用 GitHub Pages。若选择 Pages，需要另行配置 Pages 来源和发布流程，再使用生成的 HTTPS 网址访问。

## 手机在同一 Wi-Fi 试玩

在电脑上执行：

```bash
npm run build
npm run preview -- --host 0.0.0.0
```

Vite 会输出可用网络地址。手机连接同一局域网，在浏览器输入终端输出的 `Network` 地址。`127.0.0.1` 代表设备自己，不能作为手机访问电脑的地址。

该方式要求电脑和服务持续运行。代理软件需要绕过本地地址；访客网络和无线客户端隔离可能阻止设备互通。预览服务用于本地验收，不用于直接暴露公网。

## 移植到其他界面

优先复用 `src/game.js`，把操作转换为方向指令，把返回的棋盘和位移记录交给新界面渲染。存档模块可配合新的 Storage 适配器使用，CSS 和 DOM 代码则按目标平台调整。

没有绑定账号服务、云数据库或在线图片/字体接口。项目当前未添加开源许可证；面向他人授权复用时由仓库所有者另行决定许可。
